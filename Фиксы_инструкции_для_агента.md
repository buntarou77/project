## Новые находки этого коммита

### [B-51] Reuse-detection refresh без grace-периода разлогинивает все сессии
- **Файл:** `server/src/services/auth.ts:88–95`; `src/backend/apiFetch.ts` (single-flight — переменная модуля)
- **Серьёзность:** medium
- **Что происходит:** повторное предъявление ротированного refresh теперь трактуется как кража → `revokeAllSessions`. Но однополётный refresh на фронте действует **в пределах вкладки**. Две вкладки кабинета с истёкшим access шлют refresh с одним cookie: первая ротирует, вторая видит `revoked_at` → отзыв всех сессий. Тот же эффект при потере `Set-Cookie` (обрыв мобильной сети после ответа сервера).
- **Как воспроизвести:** открыть кабинет в двух вкладках, дождаться истечения access (15 мин), нажать действие в обеих.
- **Фикс:** окно лояльности вместо мгновенного отзыва:
  ```ts
  if (found.rows[0].revoked_at) {
    const reusedRecently = await query(
      `select 1 from refresh_sessions where token_hash=$1 and revoked_at > now() - interval '30 seconds'`, [hash])
    if (!reusedRecently.rows.length) await revokeAllSessions(found.rows[0].user_id)
    return false
  }
  ```
  Дополнительно — межвкладочный лок (`navigator.locks` / `BroadcastChannel`).

### [B-52] Напоминания можно включить только на экране «Готово»

### [B-54] Без SMTP владелец не получает никаких уведомлений

### [B-01] Многодневная фикс-услуга: цена × «кратность пакетов × число дней»
- **Файл:** `server/src/services/bookings.ts:261`, `:454`; `src/core/price.ts:108–109`
- **Серьёзность:** critical
- **Что происходит:** при `fullDay=false`, `multiDayMax>1`, `priceType='fixed'` в ядро уходит суммарная длительность всех дней; `k = ceil(total/base)`, затем `qty = k * windows.length` — кратность применена дважды. Витрина считает иначе.
- **Как воспроизвести:** fixed 5000 ₽ / 120 мин, `multiDayMax:3`, график 10:00–21:00, 2 дня → в заявке 110 000 ₽ вместо 10 000 ₽.
- **Фикс:** `durationMin: service.priceType === 'fixed' && fdw ? undefined : durationMin,` + тест-инвариант «оценка витрины == цена сервера».

### [B-03] Закрытые периоды считаются в UTC
- **Файл:** `server/src/services/catalog.ts:277–278`, `:287–288`
- **Серьёзность:** high
- **Что происходит:** границы `T00:00:00Z`/`T23:59:59Z` вместо таймзоны студии; для UTC+3 блокируется 03:00 закрытого дня — 02:59:59 следующего. Те же границы в поиске конфликтующих заявок.
- **Как воспроизвести:** студия `Europe/Moscow`, график 10:00–21:00, закрыть зал на 01.12 → слоты 10:00–12:00 01.12 свободны, 02.12 заблокированы.
- **Фикс:** `zonedToUtcMs(tz, dateFrom,'00:00')` и `zonedToUtcMs(tz, addDaysToDateString(dateTo,1),'00:00')`, интервал `[)`; `tz` передавать в `upsertClosedPeriod`.

### [B-04] `closed_periods`: upsert по глобальному `id` перезаписывает чужую студию
- **Файл:** `server/src/services/catalog.ts:271`; `src/owner/Settings.tsx:1423`; `server/migrations/0001_express_init.sql:201–208`
- **Серьёзность:** high

- **Фикс:** PK `(studio_id,id)` + `on conflict (studio_id,id)`; id генерировать сервером (`randomUUID()`).

### [B-05] `removeUploadFiles`: path traversal → удаление произвольных файлов

## Оценка проекта в целом

**Сильные стороны.** Чистое ядро, общее для клиента, демо, сервера и edge; единственный слой маппинга; адаптеры бэкендов; EXCLUDE-констрейнт вместо «проверил-и-вставил»; идемпотентность; хеширование токенов; анонимизация; составные PK; демо-режим без базы. Процесс за три ревизии заметно вырос: фиксы адресные, каждый с регрессионным тестом, грабли дописываются в `AGENTS.md`.

**Системные риски (важнее отдельных багов).**
1. **Деньги не покрыты инвариантом.** B-01 живёт третью ревизию. Нужен один тест «оценка == цена» на матрице `fixed/hourly × fullDay × multiDay × offsite × аддоны × ставки`, а не отдельные сценарии.
2. **Изоляция тенантов держится на дисциплине.** `studio_id` в каждом `WHERE` — вопрос внимательности; `closed_periods` это уже показал. Лечится RLS с `app.studio_id` или CI-проверкой запросов.
3. **Три бэкенда расходятся.** Supabase-edge отстаёт даже по правилу выезда. Нужен выбор: удалить или сделать тонкой обёрткой.
4. **Таймзоны: ядро корректно, периферия — нет.** Запрет на конструирование дат вне `core` (grep-правило в CI).
5. **Файловая система как второй источник истины.** Отсюда сироты, traversal, гонка уборки. Имя файла = хеш содержимого, сначала БД, GC с возрастом, всегда `resolve` + границы.
6. **Документы обгоняют реальность.** Для продукта с ПД это юридический риск.
7. **Гигиена репозитория.** Публичный репо и `project-fresh.zip` на 33 МБ в истории. До запуска — приватность, чистка истории, secret-scanning.

**Вердикт.** Крепкая, продуманная база с хорошей инженерной культурой; до готовности принимать реальных клиентов — несколько целевых итераций, а не месяцы. Критичны деньги (B-01) и корректность календаря (B-03/B-04); внешняя поверхность атаки после `287315c` существенно сузилась.
